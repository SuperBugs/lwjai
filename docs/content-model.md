# 内容模型

这个站有**四类内容**，再加一类单页。

| 集合 | 是什么 | 地址 | 目录 |
|---|---|---|---|
| `posts` | **研究稿**。一只票一篇，讲这门生意、市场押注了什么、最强反证、什么情况下认错 | `/r/<号>` | `src/content/posts/` |
| `qa` | **问答**。标题是**问题**，正文是**回答**，必标哪个智能体答的 | `/q/<号>` | `src/content/qa/` |
| `guides` | **教程**。怎么开户、怎么出入金、怎么开美国银行账户。图文并茂 | `/g/<号>` | `src/content/guides/` |
| `prompts` | **提示词**。跑出这些研究的那几份提示词，原样发出来给人抄走。**收读者投稿**，每一条都标着谁写的 | `/p/<号>` | `src/content/prompts/` |
| `pages` | 单页（现在只有「关于」） | `/a` | `src/content/pages/` |

【2026-09-21】前四类的地址是**一个全站统一的递增数字，从 1000 起**，文件名就是那个号
（`src/content/posts/1002.md` → `/r/1002`）。判据在 `src/config/entryNo.ts`：
为什么共用一个号池、为什么从 1000 起（列表页的分页也是数字地址，`/r/2` 是第 2 页）、
以及后台那条路为什么必须配一道会红的检查，都写在那个文件开头。

前缀是**一个字母**（研究 research → `/r`，问答 → `/q`，教程 guide → `/g`，
提示词 prompt → `/p`），登记在 `urlPrefix` 里；不属于任何集合的页面
（`/a` 关于、`/t` 标签、`/se` 搜索、`/ar` 归档、`/s` 标的）在 `src/config/routes.ts`。
⚠ 这两张表**管不住路由本身** —— Astro 按文件名路由，改了表不改文件名就是
全站链接指向 404 而四处全绿，所以 `scripts/gate/routes.test.ts` 双向对账。

`pages` 不编号 —— 它没有按条目的详情路由（`urlPrefix: null`），路由是一个个手写的。

### 教程为什么没有专属字段

它的 schema 是 `posts` 去掉标的那几个字段，**没有**分类枚举、没有"最后核对日期"、
没有图片审计。一篇教程本质就是一篇带图的文章 —— 给它发明一套专属结构，
代价是每次写作多几个下拉框，而写作频率恰恰是这个模块的命门。
分类用 `tags`，排序用 `pubDatetime`，和研究稿同一套。

★【2026-09-23 用户要的】**唯一的例外：选填的 `icon`**（后台「图标」，上传一张图）——
列表卡片和详情页标题前面那个小方块，嘉信开户挂嘉信的 App 图标。它不违背上面那条，
因为它不是每次写作都要碰的下拉框：一家机构传一次，没有对应机构的教程留空。
判据和理由都在 `src/config/entryIcon.ts` 文件头，这里只记三件动手之前要知道的事：

| 那一格 | 站上画什么 | 哪一档 |
|---|---|---|
| 传了 | 那张图（白底圆角方块，`src/components/EntryIcon.astro`） | **完成态** |
| 没传 | 什么都不画，卡片和原来一字不差 | **完成态**，不是待补 —— 所以没有占位框 |
| 填了但文件不在 / 格式不收 | 构建红 | 失败，一张裂开的图到不了页面上 |

- **不收 SVG**：Astro 7 的图片服务不处理 SVG，会原样透传（内容集合里的 SVG 甚至会被换成
  一个把源码内联进页面的组件）。只收 sharp 会重新编码的位图（白名单 `ENTRY_ICON_FORMATS`），
  schema 按扩展名拦一道，`EntryIcon.astro` 渲染前按文件内容探出来的格式再拦一道。
- **文件名固定是 `icon`**：Keystatic 拿字段 key 当文件名，原始文件名直接丢掉，
  所以这一格天然没有"截图文件名带账号"那条通道。它和正文截图同一个目录
  （`src/assets/guides/<号>/`）—— /_publish 和批量清理不用改就认得它；
  代价是正文里粘一张也叫 `icon.png` 的图会和它撞路径，所以正文截图的文件名清洗
  把这个名字让出来了（`src/config/uploadFilename.ts`）。
- ⚠ **Astro 文档里 `image().refine(img => img.width …)` 那种写法在这里是坏的**：
  内容层校验时 `image()` 交出来的是一串占位符，不是 ImageMetadata ——
  照着写 `img.format`，每一张图都会被拒（第一版就是这么红的）。

⚠【2026-09-21】地址换成条目号之后，后台那个搜索框对教程**彻底没用了**。
它原来用「分类前缀-主题」（`broker-ibkr-open` / `funding-wire`），
而 Keystatic 的列表页**搜索框只过滤 slug**、完全没有分组能力 ——
前缀是那个后台里唯一能当分类筛选用的东西，**这一条是真的丢了**，
不是被什么东西替代了。要按类找就用 `tags`，或者直接在列表里翻。

### 图片

截图在后台直接 Ctrl+V 粘贴即可。落盘和引用路径由 `keystatic.config.ts` 的
`imageOptions()` 决定，那段注释解释了为什么**必须是相对路径** ——
绝对路径和 `public/` 下的图**一步都不经 sharp，原图逐字节发布**（连 EXIF 一起），
而这件事在后台、页面、构建、闸门四处都看不出任何区别。

⚠ **发布闸看不见图片内容。** 截图里的账号 / 余额 / 持仓由作者在截图时自己裁掉或打码。
这一点 `docs/gate.md` 第 8 节一直写着，不因为教程模块的存在而改变。
唯一沾边的机械措施是文件名清洗（长数字串换成 `x`）—— 因为**原始文件名会原样进公网 URL**，
那是一条作者在编辑器里看不见的通道。

### 提示词：唯一一个收投稿的集合

它和教程一样是"一篇带格式的文章"，schema 也几乎一样。**多出来的两项全是投稿带来的：**

| 字段 | 三档 | 页面上 |
|---|---|---|
| `origin` | `site`（站长自己在用的，**完成态**）/ `contributed`（网友投稿，**完成态**）/ `unspecified`（哨兵，**待补**） | 时间那一行的一段字：「分享者：牢玩家」/「分享者：某某（网友投稿）」/ 虚线下划线的「分享者未标注」（【2026-09-20】原来是标题上面一张芯片） |
| `contributor` | 投稿必填。要匿名就**显式写「匿名」** | 和「网友投稿」几个字一起显示，不单独出现 |

★ 那一格叫「**分享者**」不叫「作者」（【2026-09-20 改的】）：提示词本身也是 AI 写的
（上面那张表里 prompts 的 provenance 是 `ai`），挂在这一格上的人是**把它发出来的那个**。
写「作者」等于替他认领一份不是他写的东西。

三档定义在 `src/config/promptOrigins.ts`（纯常量、零 import，理由同登记表）。
非草稿 + 哨兵 = **构建失败**，和 qa 的 `agent` 同一条 superRefine 纪律：
一份来路不明的交易提示词，读者没有任何依据判断该不该照着跑。
「投稿但署名空着」也拦 —— 空是"还没填"，匿名是一个答案，两者不许长得一样。
（两条都实跑破坏验证过：改一个字段就能让 `pnpm build` 红。）

**投稿怎么进来的：** 邮件 → 我看一遍 → 后台建一条 → 提交 → 构建。
站上没有表单、没有服务端，所以不存在自动落盘这条路；每条投稿过的是和我自己写的
稿子**完全同一条**发布闸。`contributor` 进了闸门扫描范围，
理由见 [docs/gate.md](gate.md) 7.6。

⚠ 【2026-09-20】页面上那块投稿说明（`src/components/PromptSubmit.astro`：三步流程 +
一条红线 + 一个 mailto 按钮）**按用户要求整块删掉了**，组件和六条 `t.prompts.submit*`
一起没了。现在站上说投稿的只剩 `/prompts` 顶上那句
`t.pages.promptsDesc`：「提示词分享，欢迎通过网站底部的联系方式联系投稿。」
—— 邮箱靠页脚的 `<Socials />`。改那句时**别把后半句删掉**：
这个集合收投稿，而页面上一个字都不提的话，"这个站不收投稿"和"入口没了"
在读者眼里字节级相同。

⚠ **地址里不带版本号。** 地址是一个号（`/p/1000`），标题里才写 v2 ——
出新版是改同一条（换正文、填更新时间），地址不变。版本号进地址的话，
每升一版就把已经分享出去的链接打死一次。
同理**没有 `version` 字段**：那会是一个上公网而闸门不扫的自由文本字段，
正是 2026-09-18 刚拆掉的 `sourceModel` 那个形状。

### 「这一份是谁写的」：全站唯一的判据

【2026-09-20】每个集合在登记表里要表态 `provenance`，值是**判据的名字**，不是答案：

| 登记的值 | 谁 | 算出来的三档 |
|---|---|---|
| `"by-agent"` | posts · qa | 逐条看 `agent`：真实模型 → `ai`；`human` → `human`；哨兵或查不到的 id → `unknown` |
| `"ai"` | prompts · guides | 恒为 `ai` —— 【2026-09-20 站长定的口径】提示词本身、教程本身都是模型写的 |

⚠ `"ai"` 是一句**集合级的全称断言**，改的不是判据、是人表了态。
它成立的前提是"这两个集合只有 AI 写的东西"，而 schema 管不着这件事 ——
哪天真收了一份人手写的提示词、或者自己手写了一篇教程，那一行就得换成
`by-agent` 那种逐条判据（教程还得先有作者字段）。不换的后果是页面和
**每一份下载走的 .md** 都替它认错出身，而那份文件已经离开这个站了。

★ `"human"` / `"unknown"` 今天**没有集合常量在用**，但它们不是死代码：
`by-agent` 会逐条算到 —— `agent: human` 的研究稿 / 问答落 `human`，
`agent` 还是哨兵、或者登记表里查不到那个 id 的落 `unknown`。
三句文案仍然必须两两不同（`export.test.ts` E 组钉着）。

判据落在 `src/config/provenance.ts` 的 `provenanceOf()`，
**详情页页脚和 `.md` 导出口调的是同一个函数**（同一句断言"两处只改一处"
这个仓库已经犯过两次，docs/engineering-notes.md 坑 8）。三句文案在 `t.provenance`，按语言走。

⚠【2026-09-23】**那两个调用方今天都没有了**：页脚那一句 2026-09-21 删了，
`.md` 文件头那一句 2026-09-23 随整段文件头一起删了（用户要的：下载 / 复制拿到的
就是正文原文，站方一个字都不加）。这一格和那个函数还在，是等站长决定删掉还是
另找落点 —— 见 `provenance.ts` 顶部「现状」。

★ **有详情路由却没填 `provenance` 是类型错误**（`StrictSpec` 的联合类型），
`astro check` 在 `pnpm build` 里就拦下了。这一条刻意不靠测试钉 ——
`pnpm test` 不在任何自动链路里（pre-commit 只跑暂存区闸，构建跑的是闸门 +
astro check），靠测试钉的话漏填一个集合在提交、构建、部署三处全绿。

★ 这套东西是用来替掉一句**全称断言**的：「站内所有内容都是 AI 生成」。
它在只有研究稿和问答的时候是真的，加了教程和提示词之后在全站范围内是假的，
而它当时躺在六处 —— 包括 /about 那份「完整免责声明」和每一份下载走的 .md。

⚠ 【2026-09-20 当天晚些时候】站长把 /about 免责声明的首句定成了
「**本站所有内容均为AI生成，不构成任何投资建议、操作指导、要约或推荐。**」——
也就是说**那一页上又有一句全称断言了，这次是明知故意的**。
配套的三件事同一天做了：提示词的 provenance 从 `human` 改成 `ai`、
教程从 `unknown` 改成 `ai`（上表），页面上提示词那一格从「作者」改成「分享者」。
**于是全站唯一还能算出"不是 AI 生成"的，只剩 `agent: human` 的研究稿 / 问答** ——
那一条是 schema 明确允许的例外，不许被这句全称断言压掉
（`export.test.ts` E 组有一条专门的探针钉着它）。
（`export.test.ts` 的 E 组原来有一条禁止 about.md 出现全称断言的否定断言，
同日换成了肯定断言「那一页上必须还有『不构成任何投资建议』」——
一条只禁止某种措辞的否定断言换个说法就能绕过去，比没有更糟。）

## 1. 登记表：`src/config/collections.ts`

五个集合登记在**一张表**里。这张表同时被五处读：

```
src/config/collections.ts   ← 唯一的一份
   ├── src/content.config.ts      每个集合的 loader base，以及 BLOG_PATH
   ├── src/utils/getPostPaths.ts  算详情页地址时按 dir 剥前缀、按 urlPrefix 拼路径
   ├── scripts/gate/inspect.ts    两道发布闸的扫描范围都从它推
   ├── scripts/gate/coverage.test.ts  拿磁盘上的真实目录反过来对账
   └── scripts/content/plan.ts    批量清理扫哪几个目录、报表里叫什么名字
```

**这个文件里一个 `import` 都没有，是刻意的。** 它要被裸 `tsx` 跑的
`scripts/gate/*` 引用（pre-commit 钩子、Cloudflare 构建第一步），那里没有 Astro 的
`astro:content` 虚拟模块，也没有 `@/` 别名解析。而且依赖方向已经是
`content.config.ts → scripts/gate/rules.ts`，反过来引会成环。

### 加一个新集合要做什么

1. 在登记表里加一行（`scanned` 一般是 `true`）
2. 在 `src/content.config.ts` 里加 schema + 加进 `collections` 导出
3. 在 `keystatic.config.ts` 里加后台集合
4. 在 `scripts/content/plan.ts` 的 `PRUNE_SCOPE` 里表态：参与批量清理
   （`timeField: "pubDatetime"`），还是不参与（`timeField: null` + 写明理由）
5. 建目录、写页面

**第 1 步忘了会怎样：`pnpm test` 直接红。** `scripts/gate/coverage.test.ts`
枚举 `src/content/` 下的真实目录，和登记表**双向**对账 ——
磁盘上有表里没有 → 失败（新集合没进闸门）；表里有磁盘上没有 → 失败（路径写错）。

**第 4 步忘了会怎样：`pnpm test` 也直接红**（`scripts/content/prune.test.ts`
的头三条，同样是双向对账）。这一步的失败方向是安全的 —— 漏了 = 那个集合永远不会
被批量清理，少删东西 —— 但它**零症状**：清理命令照常跑、照常报「命中 0 条」，
和"这个区间里真的没有老稿"在屏幕上一模一样。所以要的是**表过态**，不是"表里有它"。

这条测试存在的理由：2026-09-18 之前，新建一个 `src/content/qa/` 而不动闸门，
**两道闸都不扫它，一个字的报错都没有** ——`pnpm gate` 照常印
「✓ 没命中已知的危险说法」、退出码 0。`src/content/pages/about.md` 从建站起
就一直处在这个状态（它是公网页，正文里还有一句 block 档的「不写我自己的仓位」）。

## 2. 字段名是接口，不许随便改

`qa` 的字段名**刻意和 `posts` 对齐**，因为下面这些东西按名字取值：

| 字段 | 谁在按名字读它 | 改名的后果 |
|---|---|---|
| `title` | `scripts/gate/inspect.ts` | **零症状漏扫**。inspect 用 `data.title ?? ""` 兜底 —— 换成 `question` 之后闸门会"成功扫描"一个空标题，报告里照常计入篇数，而问题文本从未进过 `scan()` |
| `description` | 同上 + RSS item + `<meta>` + 列表页 | 同上；RSS 里变成空正文且不报错 |
| `pubDatetime` · `modDatetime` · `timezone` | `Datetime.astro` · `postFilter.ts` · `createdOrder.ts`（列表的先后只看 `pubDatetime`） | 类型会报错，但报的是「Datetime 缺 prop」，不是「你的 schema 名字取错了」 |
| `draft` | `postFilter.ts` | 草稿会开始生成公开页面 |
| `tags` | `getUniqueTags` | 缺字段时 `slugify(undefined)` 抛错，而报错信息看不出是哪个集合 |

所以**问题存在 `title` 里，回答存在正文里** —— 不叫 `question` / `answer`。

## 3. 「谁答的」：`src/config/agents.ts` + `src/config/models.ts`

**两维**（【2026-09-20 拆开的】）：`agent` 是**哪个智能体**（Google Spark / OpenAI ChatGPT /
Anthropic Claude / OpenAI Codex / 我自己），`model` 是那个智能体**底下跑的是哪个模型**
（GPT-5 / Opus-5 / Gemini-3-Pro …）。智能体的显示名就是「厂商 产品」；模型的显示名
**用连字符连起来、不用空格**（GPT-6-Pro、Gemini-3-Pro），而且
**不重复智能体名里的词**（Anthropic Claude 底下是 Opus-5，不是 Claude Opus 5），
后台下拉框和芯片都不再缀厂商。
原来只有一维、填的是模型名；改成两维是因为现在真正在用的是智能体产品，
同一个产品底下的模型会换，换了答案就不一样 —— 读者要靠这两格一起判断。
两张都是封闭登记表，`z.enum(AGENT_IDS)` / `z.enum(MODEL_IDS)` 钉着，后台下拉框直接从它们生成。

★【2026-09-21】**两格现在是联动的**：每个模型在登记表里记着"能在哪些智能体底下跑"，
换了智能体、模型和新智能体矛盾时后台自动跟上，而一个登记表里不存在的组合
（`agent: spark` + `model: gpt-6-pro`）**构建期直接红**。
数据形状、三档、以及这套东西**做不到**什么，写在下面「加一个智能体 / 一个模型」那一节。

**为什么不是自由文本**：同一个智能体会被写成 `Claude Code` / `claude-code` /
`ClaudeCode` / `Claude` 四个名字，而**任何一处都不报错** ——
屏幕上只是多出几个看起来陌生的名字。

还有一层更要紧的理由：这个字段**上公网，而发布闸不扫它**
（闸门扫的是 title / description / symbolName / tags / 正文）。
2026-09-18 之前 `posts` 有一个叫 `sourceModel` 的自由文本字段干这件事，
往里填「gemini-3-pro（跑在 example_server 上）」本该命中 `internal_system` 规则，
**却完全不会触发**。换成封闭枚举之后这个泄露向量消失 ——
枚举里只有那么几个 id，夹带不进自由文本。

### 智能体：三档，不许压成两档

| `agent` 的值 | 含义 | 页面上 |
|---|---|---|
| 某个 AI 智能体（`codex` / `claude` / `spark`） | AI 答的 | 显示名字 + 厂商（「以下是模型的原话」那句【2026-09-20】挪进了「关于」页；导出的 .md 里原来还带一份，【2026-09-23】随导出件改成正文原文一起拿掉了） |
| `human` | **我自己写的。这是完成态** | 显示「我自己」 |
| `unspecified`（哨兵） | **还没选 / 没记录。这是待补** | 显示「来源未标注」，虚线边；qa 非草稿时**构建直接失败** |

判据是登记表里的 `kind` 字段（`ai` / `human` / `unspecified`），
**不是比对 `id === "human"` 这种字面量** —— 字面量散在各处之后，
哪天加一个「自建的多步研究智能体」（是 AI）或者「某位朋友」（不是 AI），
就得去翻每一处比对点，而漏掉一处的症状是**页面对着一段人写的字说「以下是模型的原话」**。

### 模型：「没有」分三种，只有一种画成待补

| `agent` 的档 | `model` 的值 | 页面上（`AgentModelChip` 括号里那一格） |
|---|---|---|
| AI 智能体 | 登记表里的某个模型 | 实线芯片，印模型名 |
| AI 智能体 | `unspecified` | 虚线「模型未标注」（**待补**）；qa 非草稿时**构建直接失败**，posts 只提醒 |
| `human` | 必须是 `unspecified` | **什么都不画、不写**：人写的没有模型这回事，填了模型构建失败 |
| `unspecified` | `unspecified` | 什么都不画：旁边那句「来源未标注」已经说完了 |
| `unspecified` | 登记表里的某个模型 | 照画：「知道模型、不知道产品」是真会发生的（直接调 API） |

芯片和分享卡署名读的都是它（【2026-09-23】`.md` 导出口原来也读、写进文件头，导出件改成正文原文之后不再写）。

两维的一致性由 `content.config.ts` 的 `checkAgentModel` 管（posts / qa 共用一份）。
它现在有三条：「我自己」写的不许填模型、**这个组合得在登记表里存在**（下一节）、
以及 qa 那条"非草稿 + AI 答的必须标模型"。前两条**和草稿无关，一律拦** ——
它们不是"还没填完"，是两格互相矛盾。

### 为什么需要哨兵

Keystatic 的 `fields.select` 的 `defaultValue` 是**必填的、永远有值**
（类型定义里没有 `?`，且 select 完全没有 validation 入参）。
也就是说后台不存在"这个下拉框是空的"这一档 —— 存盘时那一格一定带着某个值。

哨兵的作用是让**「还没选 / 没记录」成为一个显式、能被 schema 拦下来的状态**：
页面上它显示成「来源未标注」（不是空白），qa 非草稿时它让构建直接失败。
没有这一档的话，"我没记"只能靠留空表达，而留空和"这是我自己写的"在文件里字节级相同。

⚠ **【2026-09-21 用户改了后台的默认值】** posts / qa 的 `agent` / `model` 两格现在默认
落在**登记表里排第一的那个智能体**（`DEFAULT_AGENT`）和**它底下的第一个模型**
（`DEFAULT_MODEL`）上，下拉里哨兵挪到了最后一项。理由是手工活：站长每天用的就是那一套。
换默认值的做法是去后台「智能体与模型」页把那一行拖到最前 ——
登记表的顺序 = 下拉的顺序 = 默认值（`registry.test.ts` 钉着）。

★ 模型那一格的默认值**当天晚些时候跟着联动改过一次**：原来是"整张表里排第一的模型"，
而那个值和上面那格毫无关系 —— 把 GPT-5 拖到模型表最前，新建表单就默认落在
「Google Spark + GPT-5」这个不存在的组合上，**而四处全绿**。
连带一件事：模型下拉的**第一项不再必然是默认值**（下拉是一整张表，没法按当前智能体过滤），
"默认是哪个"靠每一项后面缀的归属看出来。

代价是真的，写在这里免得被忘掉：这一格**不填也有值**，换了智能体而忘了改，
文件上看不出这是默认值还是人挑的，闸门不管、zod 不管、页面上和真填过的一模一样。
连带的一件事 —— **qa 那条「非草稿 + 哨兵 → 构建失败」对后台建的条目已经不会触发**
（它拦的是哨兵，而后台现在填不出哨兵）。它仍然拦手写的 frontmatter 和
`pnpm content:import` / `/_import` 进来的：那两条路的默认值**刻意还是哨兵**，
因为那边的值是模型吐出来的。

★ `prompts` 的 `origin`（这份提示词是谁写的）**没跟着改**，默认值仍然是哨兵：
那一格是**替别人认领东西**的地方（一份投稿默认显示成"站长自己在用的"），
和"我每天都用同一个智能体"不是一类事。

### 加一个智能体 / 一个模型：后台「智能体与模型」页

【2026-09-20】数据在 `src/data/registry.json`，后台左侧「智能体与模型」那一页
（Keystatic singleton）写它；`agents.ts` / `models.ts` 只负责读进来、套上哨兵、验一遍
（`src/config/registry.ts`）。加一个模型（GPT-6-Pro）就是在那一页加一行、存盘。

- **哨兵不在那一页。** 「未标注」和「我自己」写死在代码里 —— 它们是分档的判据，
  不是产品；登记表里出现这两个 id 会在 import 时直接抛。
- **`id` 定了就不要再改** —— 它进 frontmatter 和地址，改了等于把已经发出去的条目
  一起变成「来源未标注」。显示名随时可以改。
- **那一页写的字上公网**（芯片、悬停提示、问答署名、分享卡），所以
  发布闸的三道都扫它（`inspectRegistry`），说明栏里别写内部系统的名字。
- 后台正开着的研究稿 / 问答编辑页要刷新一次才看得到新选项；构建期永远读最新的一份。

#### 模型的「能在哪些智能体底下跑」：三档【2026-09-21 加】

这一格（JSON 里是模型那一半的 `agents`，值是智能体的 id）是**两格联动的全部数据**。
三档，判据只有 `src/config/models.ts` 的 `modelScope()` 一处：

| 那一格 | 含义 | 后台下拉里 | 构建期 |
|---|---|---|---|
| 勾了几个产品 | **只在这几个底下跑**（完成态） | 「Gemini-3-Pro（Google Spark）」 | 和别的智能体一起出现 → **直接红** |
| 只勾「不限智能体」（`"*"`） | 看过了，**哪儿都能跑**（完成态） | 「Grok-4（不限智能体）」 | 不拦 |
| 一个都不勾 | **还没标**（待补） | 「Foo（归属未标注）」 | 不拦 —— **不知道就不许断言错配** |

★ 后两档**不许压成一档**。把"还没标"当成"不限"的话，在后台加一个模型忘了勾归属，
它就自称能在任何智能体底下跑，错配判据对它整条失效，而没有任何一处看得出来。
它们在后台那一格（勾没勾）和模型下拉的标签（缀的字不一样）上都分得开。

★ **为什么挂在模型这一边，而不是把模型嵌进智能体底下**：同一个模型确实会跑在两个
智能体底下（GPT 系列在 ChatGPT 和 Codex 底下都有），嵌套会逼出重复的 id，
而登记表的重复 id 检查会直接抛。

★ **联动做不到的那件事，照实写在这**：模型下拉**没法按当前选中的智能体过滤**。
`fields.select` 的 options 在配置求值那一刻就定死了，而可见的那个列表是 react-aria 渲的，
在 DOM 里增删它就是和 React 打架。所以人**仍然挑得到**一个错配的组合 ——
兜底是标签上的归属和构建期那条拦截，不是把它挡住。
（自动那一步在 `src/dev/keystaticAgentModel.ts`：**只修矛盾，从不替人回答** ——
当前停在「未标注」就一直是「未标注」，替它填一个模型等于编出处。）

⚠ **删一个智能体之前，先把勾着它的模型那几行取消勾选。** 反过来的话登记表读不进来
（`parseRegistry` 对账那一条直接抛），而后台自己也读它 —— **整个后台打不开**，
只能手改 `src/data/registry.json`。这是"宁可红"的代价：悄悄丢掉一个认不出来的归属，
等于替这个模型改写它属于谁，而那会让一批本来合法的条目突然构建失败、
或者反过来放行一个真错配。

## 4. 标的

`symbols`（**一串**代码）+ `symbolSource`（**怎么认出来的**）。
公司中英文名**不在条目上**，在标的表里（下一节）。

### 4.1 一条内容可以讲好几只票【2026-09-22 用户要的】

原话是「问答添加文章的时候…还可以 label list group 选择多个标的，因为一个问答可能
涉及多个标的」。站上真实的例子就是那两条「CPU 为什么暴涨」——它同时讲 ARM / INTC / AMD，
而那一格当时只放得下一只，于是它一只都没填。

| 集合 | 后台那一格 | 上限 |
|---|---|---|
| `posts` 研究稿 | 多选（`symbolsField()`） | **至多一只**（`symbolsField(1)`，构建期拦） |
| `qa` 问答 | 多选 | 不限 |

★ **两个集合的字段形状统一成列表**，「一篇研究稿至多一只主标的」那条编辑纪律
（想写两只就写两篇，否则 `/s/TSLA` 那一页会混进「其实主要在讲 NVDA」的条目）保留下来，
但它**从结构性变成了一条会红的检查** —— 原来那一格是单个字符串，填不下第二只；
现在后台里勾得到两只，要到构建那一刻才拦下来。这是形状统一付的账，
写在 `content.config.ts` 的 `symbolsField()` 上，免得下一个人以为是漏改。

★ 勾上的**每一只**的 `/s/<代码>` 页和分支 feed 都会收进这一条（判据是 `some()`，
不是相等）；详情页一只画一张芯片，「相关条目」按**交集**算 ——
要求两边完全一样的话，那条多标的问答会和谁都不相关，而页面上只会少一块，不报错。

⚠ Keystatic 自己那张列表里 `symbol` 那一列**没了**：`columns` 只吃 text / select / datetime /
date / checkbox / number / url / slug，`fields.multiselect` 放进去配置求值那一刻就抛
（`tags` 一直进不来也是这个原因）。在那张表里这一列是真的丢了，不是被什么东西替代了。
【2026-09-23】后台的列表页换成了自己画的（`src/dev/keystaticEntryList.ts`：搜索 + 新的在前 +
分页），「标的」那一列在那边回来了 —— 它从 .md 直接读、名字查标的表，不走 `columns`。
Keystatic 那张表只在我们的列表读不到数据时才露出来，那时仍然没有这一列。

### 4.2 标的表：公司名只有一处

| 哪一层 | 在哪儿 |
|---|---|
| 数据 | `src/data/symbols.json`（后台左侧「标的」那一页 singleton 写它） |
| 判据 | `src/config/symbols.ts`：`parseSymbols()` 验表、`symbolOptions()` 给后台、`unknownSymbols()` 判"在不在表里"、`symbolNames()` 查名字 |
| 后台那两格 | `keystatic.config.ts` 的 `symbolsField()` 工厂（`fields.multiselect`，**两格共用一个**） |
| 不经后台进来的 | `src/content.config.ts` 的 `symbolsField()`（构建期拦，两个集合共用一个工厂） |
| 粘贴导入 | 表外的代码**自动登记一行**并报一句（见下） |
| 过闸 | 名字上公网，路径在 `collections.ts` 的 `SCANNED_DATA_FILES`，三道闸都扫 |

**为什么名字要搬进表里：** 多选之后一格里勾着三只票，名字没地方逐只填。
顺带治掉的是一件老问题 —— 名字原来是**每条内容各填一份**，同一只票在两条里写成两个
名字不会有任何报错，`/s/<代码>` 那一页只能"以最近写的那条为准"
（`getUniqueSymbols.ts` 里那段 latest-wins 就是为此存在的，现在删掉了）。

**和标签表刻意不一样的一处 ——表外的值怎么办：**

| | 标签 | 标的 |
|---|---|---|
| 构建期遇到表外的值 | 红 | 红 |
| **粘贴导入遇到表外的值** | **丢掉并报一行** | **自动加一行并报一行** |

★ 理由在"丢掉它的代价"上：一个模型现编的标签丢掉只是少一个分类；而**丢掉标的等于
把这条内容从 `/s/<代码>` 上整个摘出去**，那正是它最该出现的地方。代码又是机器可验的
标识符（`SYMBOL_RE`），不像标签那样会长出「财报」「财报解读」这种同义写法。
判据是 `withSymbolRow()`，两个导入口（CLI 和 `/_import`）经 `registerSymbols()` 读同一份。

★ **代码就是身份**（进 frontmatter、进 `/s/<代码>` 那段地址），定了不要改；名字随时能改。
删一只票的顺序和标签表一样**是反的**：先去用着它的条目上取消勾选，再回来删这一行 ——
反过来做那几条在后台点不开（`multiselect` 的 parse 对表外的值直接抛）。

★ 表里同时出现 `BRK.B` 和 `BRK-B` 会**直接抛**：它们在 `/s/brk-b` 上是同一页，
两行抢同一个地址，而后台、构建、闸门四处全绿。归一判据只有 `symbol.ts` 的 `symbolKey()`
一处（`related.ts` 的 `normalizeSymbol()` 和 `getUniqueSymbols.ts` 的 `symbolSlug()` 都读它 ——
2026-09-22 之前那两处各写死了一份相同的正则）。

⚠ `unknownSymbols()` 反过来是**字面量比对**，不走归一：后台那一格是从表里勾的，
放宽的话手写一个 `BRK-B`（而表里是 `BRK.B`）能过构建，**而那一条在后台打不开**。
构建绿、后台红是最难查的一种。

### 4.3 `symbolSource`

`symbolSource` 是四档封闭枚举，第四档不许压扁：

- `subject_line` —— 从正文的「研究对象：CODE（公司名）」行认出来的（提示词自带这行）
- `title` —— 从标题里的代码认出来的
- `manual` —— 人自己填的
- `unknown` —— **没认出来**。这是「我不知道」，要人回来补

`symbol` 为空时 `symbolSource` 仍然有意义：
`unknown` + 空 = 没认出来（**待办**）；`manual` + 空 = 人看过了，确认它不讲单只票（**完成态**）。

`/s` 索引页和 `/s/<代码>` 页同时收两个集合，计数**分开报**
（「3 篇研究 · 2 条问答」）—— 一个混合的数字会让读者分不清。
计数文案在 `src/utils/coverageLabel.ts`，/s 两页共用一份。

`/s/<代码>` 和研究稿 / 问答详情页上各有一行「去原始来源核对」：SEC EDGAR · Yahoo Finance ·
Nasdaq 直达链接（表在 `src/config/symbolLookups.ts`，纯外链、零服务端）。三家的代码写法
不一样（`BRK-B` / `brk.b`），换算有测试钉着（`scripts/gate/symbolLookups.test.ts`）。

## 4.5 标签：一张封闭词表【2026-09-21 加】

`tags` 从"四个集合各自手打的文本框"换成了**从一张表里勾**：

| 哪一层 | 在哪儿 |
|---|---|
| 数据 | `src/data/tags.json`（后台左侧「标签」那一页 singleton 写它） |
| 判据 | `src/config/tags.ts`：`parseTags()` 验表、`tagOptions()` 给后台、`unknownTags()` 判"在不在表里" |
| 后台那四格 | `keystatic.config.ts` 的 `tagsField()` 工厂（`fields.multiselect`，**四格共用一个**） |
| 不经后台进来的 | `src/content.config.ts` 的 `tagsField()`（构建期拦，四个集合共用一个工厂） |
| 粘贴导入 | `planImport()` 把表外的标签**丢掉并报一行**（模型最爱现编标签） |
| 新建时的默认值 | 只有研究稿：`POSTS_DEFAULT_TAGS`（「个股研究」），见本节最后一段 |
| 过闸 | 它上公网，路径在 `collections.ts` 的 `SCANNED_DATA_FILES`，三道闸都扫 |

### 为什么要封闭

`/t` 索引页和 `/t/<标签>` 列表页是**按标签折叠**的。手打的代价不是难看，是同一类内容
被拆成两页：「财报」和「财报解读」在后台看起来只是手滑，在站上是两个各有一篇的孤儿页面，
而后台、构建、闸门四处全绿。和 `agent` / `model` 从自由文本换成封闭枚举是同一条理由。

### 和智能体 / 模型那张表**刻意不一样**：没有 id 这一层

那边是 `id`（进 frontmatter，定了不改）+ `name`（显示名，随便改）；标签只有一格，
因为地址 `/t/<标签>` 就是从这几个字算出来的 —— 再拆一层 id 是另一件事
（docs/engineering-notes.md 坑 4：中文标签的地址是 `%E7%AB%99%E5%8A%A1`，真要治是在 `slugify.ts` 里
加一层英文映射）。

代价说清楚：**改名 = 改所有用着它的条目里的那个词**。它不会静默烂掉 —— `unknownTags()`
在构建期当场红，并指出是哪一条用着哪个表里没有的标签。红得早，不是坏得安静。

### ⚠ 删标签的顺序是反的，而且反了就出不来

要删一个标签：**先**去用着它的条目上取消勾选（那时它们还打得开），**再**回来删表里那一行。

倒过来做的话，那几条在后台**点不开**（Keystatic 的 `multiselect` 对表外的值直接抛：
`Field validation failed: tags: Must be an array with one of …`），而要改的那一格
恰恰在打不开的那张表单里 —— 只能先把那一行加回去，或者手改 `.md`。
2026-09-21 实测撞到过一次（表里删了「期权」，而 `src/content/prompts/1000.md` 还用着它）。

这条"打不开并说明原因"是**对的那一头**，和 `fields.select` 那条同一个取舍：
比静默把那几个标签丢掉强得多 —— 后者等于悄悄把一条内容从它所属的分类里摘出去。

### 研究稿新建时默认勾「个股研究」【2026-09-23 加】

用户要的：后台新建一篇研究稿，「标签」那一格预先勾着「个股研究」（站上的研究稿几乎篇篇是
逐只票的研究）。常量是 `src/config/tags.ts` 的 `POSTS_DEFAULT_TAGS`，经 `tagsField()` 的
第二个参数只接到研究稿那一格；问答 / 教程 / 提示词照旧一个都不勾。

- **只管后台新建那一刻。** 已有条目不动（没打标签的打开还是没打）；构建期 schema 不补
  （补的话刻意不打标签的稿子会被悄悄归进那个标签页）；两个粘贴导入口也不跟（标签是模型
  照着 `{{tags}}` 从表里挑的）。
- **代价和 `agent` 那一格的默认值同一种**：存下来的文件看不出这个勾是默认的还是人勾的。
  讲宏观、讲方法论的研究稿忘了取消，就会出现在这个标签页里。那一格的说明里有一句提醒。
- **默认值先对着表滤一遍**（`resolveDefaultTags()`）。Keystatic 的 `fields.multiselect`
  不核对默认值在不在选项里（`fields.select` 会在配置求值时就抛）：表里改名 / 删掉「个股研究」
  之后，原样传进去的默认值在表单上勾不出来、存盘时却照样写进新稿子，那一条随后在后台打不开。
- 滤掉的那几个由那一格的说明讲出来（`defaultTagsNote()`），**三档字节两两不同**：勾上了 /
  该勾没勾（表里已经没有它，说出去哪儿改）/ 这个集合没有默认（空串，说明一字不差）。
- 刻意**没有**「表里还有没有它」那条测试：`pnpm test` 在 build 链里，为一个只让后台少勾一下的
  问题拦下整站发布不值。钉子是 `scripts/gate/tags.test.ts` 的 G 组。

## 5. 互链【2026-09-20 加】

四个集合之间原来一条链接都没有。现在有三种关系，外加一个按智能体的索引。

### 5.1 问题组 / 选题组：`questionKey`（qa ＋ posts）

**【2026-09-20】两个集合共用这一个字段和这一套判据。** 问答是「同一个问题问了几个
智能体」，研究稿是「同一个选题让几个智能体各写一份」—— 同一只票同一个角度，
换个智能体跑出来的结论不一样，那正是这个站要给读者看的东西。

⚠ **字段名沿用 `questionKey` 是刻意的**（用户定的）：为了不给一个"换个名字"的改动
去动二十来处引用（导入管线、常用提示词 JSON、导出口、五组测试、两份文档）。
所以**别按字面理解它** —— 在研究稿里它是「选题组」，后台和页面上的措辞也是这么写的。
支持哪些集合写在 `src/utils/related.ts` 的 `GROUPED_COLLECTIONS` 一处，
加第三个集合是改那一行，不是去四个地方各加一个 `collection === "…"`。

同一个问题问了几个智能体，详情页把这几条回答摆在一起 —— 问答模块存在的理由就是这个对照。

**【2026-09-20 改了两处】**

① **后台那一格是下拉，不再手填。** 新建问答时它排在**最前面**，是这张表的模式开关：
「① 这是一个新问题」／「② 补一个回答：<已有问题的原文>」。
选项从 `src/content/qa/*.md` 现推（`keystatic.config.ts` 的 `questionOptions()`）。
★ 这不只是省事 —— 手填时**同组的每一条都得敲成一模一样**，敲错一个字母不报错，
只是那两条回答各自孤零零。下拉把那条路堵死了。

② **归组的判据是「填了用键，没填用自己的地址」**（`src/utils/related.ts` 的
`qaGroupKey()`，有单测）。一组里的**第一条没有键** —— 它被创建的时候还没有
"已有问题"可挑；后来的回答指向它的地址。
★ 所以老稿子那种"几条互相填同一个键"**一个字都不用改**，两种写法在新判据下都成立。

- **封闭格式**：小写 ASCII slug（`src/config/questionKey.ts`）。它上公网而闸门不扫，
  所以不许是自由文本 —— 和文件名同一类东西。后台换成下拉之后，那条正则只在构建期兜底：
  落到它，说明有人绕过后台手写了 frontmatter。
- **三档不许压**：没填、也没有别的回答指向本条 = 只问过一次（完成态，整块不渲染）；
  填了但没对上 = 页面印「这个问题目前只有这一条回答」（多半是选的那条被删了，
  这一句是唯一的线索）；有同组的 = 列出来。
  ⚠ 详情页那个判断**不能写成 `questionKey &&`** —— 一组里的第一条没有键，
  那样写它的整块会消失，而它明明有两条回答指向它。
- **两处都要有，不是重复**：正文**上方**一排可点的切换（`QaAnswerSwitch.astro`，
  谁答的 + 什么模型，本条画成当前项），正文**下方**仍是带摘要的卡片列表。
  读之前要的是"有几条、都是谁"，读完之后要的是"下一条讲了什么"。
  【2026-09-20 之前只有下方那一块】—— 读者得先读完一整篇才知道旁边还有可对照的。
- 导出的 .md **不带**它 —— 【2026-09-23】起导出件就是正文原文，frontmatter 里的东西一样都不带。

### 5.2 研究稿引用提示词：`prompt`（posts）

`prompt: <提示词的 id>`，Astro 的 `reference("prompts")`。页脚一行「这篇是用这份提示词
跑出来的：…」链过去，提示词那一页反向列出「用这份提示词跑出来的研究」。

⚠ **Astro 7 的 `reference()` 不核对目标存在**（runtime.js 的 createReference 只把字符串
包成 `{ id, collection }`）。`src/utils/resolvePromptRef.ts` 在研究稿详情页查
（【2026-09-23】之前 .md 导出口也查，导出件改成正文原文之后只剩详情页这一处）：
找不到、是草稿、还没到发布时间 → **抛，构建红**。宁可红，不要一个看起来正常的 404 链接。
没引用 = 这篇不是用站上的提示词跑的（完成态），页面上什么都不显示。

导出的 .md 里原来写着解析好的 `prompt: "<标题>"` + `prompt_url`；【2026-09-23】起
导出件就是正文原文，这两行和别的 frontmatter 一起没了（`export.test.ts` B / C 组钉着导出 = 正文）。

### 5.3 详情页的「相关条目」

判据都在 `src/utils/related.ts`（零 import，`scripts/gate/related.test.ts` 钉着
「本篇不许列进去」「同一条不许在一页上出现两次」）：

| 在哪 | 列什么 | 一条都没有时 |
|---|---|---|
| 研究稿 / 问答页脚 | 同一只票的其他研究和问答（两个集合） | 有 symbol → 「这只票目前只有这一篇」；没 symbol → 整块不渲染（完成态） |
| 问答正文之后 | 同一个问题、其他智能体的回答（5.1） | 有键 → 「目前只有这一条回答」；没键 → 不渲染 |
| 提示词页尾 | `prompt` 指向它的研究稿 | 整块不渲染（规则手册本来就不出研究，"还没有"没有信息量） |

组件是 `src/components/RelatedEntries.astro`，带 `data-pagefind-ignore`（列的是别的条目的
标题和摘要，不挡掉会污染本页的搜索索引）和 `data-print-hide`。

### 5.4 没有「智能体索引」

【2026-09-20】站上曾有一套 `/ai`、`/ai/<id>`（按智能体列内容，`AgentChip` 链过去），
同一天拆掉了：谁答的、用的什么模型是每条内容上的两张芯片，是给读者看的**出处**，
不是一种组织内容的方式。想按智能体找内容，站内搜索（Pagefind）能搜到芯片上的名字。
**别把它加回来** —— 加回来就得连导航项、面包屑、按智能体的分支 RSS 一起回来。

## 6. 后台（Keystatic）和 schema 的对账

后台写 frontmatter，zod 读 frontmatter。两边对不上的症状**通常是零报错的**：

- Astro 的 collection schema **非 strict**，多余的 frontmatter 键被**静默丢掉**
  —— 后台里填了、页面上没有，两边都不报错
- Keystatic 的空 `fields.text` 序列化成 `undefined`，**整个 key 从 frontmatter 里消失**
  （不是写成 `""`）；而 `multiselect` 的空数组会老实写成 `tags: []`
- `fields.select` 的 `defaultValue` 不在 options 里时，**配置求值那一刻就 throw**
  （整个后台打不开）—— 所以 `DEFAULT_AGENT` / `DEFAULT_MODEL` 必须是
  `agentOptions()` / `modelOptions()` 里的一项，登记表空着时它们退回哨兵
- `fields.multiselect` 的 `parse` 对**不在 options 里的值直接抛**（和 select 同一个脾气）：
  「智能体与模型」页里，模型勾着一个已经被删掉的智能体时，那一条在后台**打不开**。
  这是对的那一头（比静默丢掉强），但它和登记表自己的对账（`parseRegistry`）**是两道**，
  后者更早、更硬：整个后台都打不开。删智能体前先取消勾选。
  ★【2026-09-21】`tags` 现在也是 `multiselect`，所以**同一条脾气落到了内容条目上**：
  表里删掉一个还被用着的标签，那几条内容在后台点不开 —— 顺序和补救见 4.5 节最后一段
- `fields.datetime` 那几格**输入的是北京时间，存盘的是 UTC**：换算在
  `keystatic.config.ts` 的 `beijingDatetime()` 里包了一层
  （判据 `src/config/beijingTime.ts`，纯函数、有测试）。
  ⚠ 再加一格时间要走那个工厂 —— 直接写 `fields.datetime` 的话新那一格填的是 UTC、
  和隔壁那格差 8 小时，而四处全绿（`beijingTime.test.ts` 钉着"只许有一处"）

改了任一边，**另一边要对着改**。没有机械闸守这条 —— 这是这个内容模型目前
最薄的一环，写在这里是为了让下一个人知道。
