# 安全策略

## 报告方式

请勿通过公开 Issue 报告安全问题，请使用仓库页面的 **Security → Report a vulnerability**（私密漏洞报告）。

以下情况同样请私下报告：

- 仓库（含历史）中出现疑似真实的个人信息：持仓、账号、联系方式、密钥、本机路径；
- 可使发布闸在未执行的情况下显示通过的方法。

## 范围

| 组件             | 说明                                                                                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 公网站点         | 构建产物为静态文件，生产环境无服务端代码。正文中的 HTML 经 `rehype-sanitize` 过滤，白名单见 `src/config/sanitize.ts`                                  |
| 本地后台与工具页 | `/keystatic`、`/_publish`、`/_import`、`/_tidy` 等仅在开发环境注入，具备写盘与 git 提交、推送能力。`/_publish` 的同源校验不构成认证，请勿将开发服务器暴露到网络 |
| 发布闸           | 基于词表，不保证完整拦截                                                                                                                             |
| 导入的模型输出   | 视为不可信输入，经过滤与发布闸校验后仍需人工审阅                                                                                                     |

## 不属于安全问题的情况

模型实际写出、但未被发布闸拦截（或被误拦）的表述，请通过 Issue 的「发布闸漏网 / 误伤」模板提交。
示例中的数字请使用虚构值。
