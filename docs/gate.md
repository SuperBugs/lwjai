# 发布闸

> 这个站唯一一件**出了事没法补救**的事，是把仓位信息发上公网。
> 网页被抓过一次，撤回也撤不干净。这份文档说的是拦它的那套东西。

## 1. 为什么需要它

红线是「持仓 / 成本 / 数量 / 方向 / 凭证，一个字节都不许上站」。站是公网明面，
而写研究的人自己在交易 —— 研究是在装着自己仓位的上下文里跑出来的。

结构化的数据能靠"schema 里根本没有这个字段"来挡；这一层过的是**人和模型写的自由文本** —— 你让 Gemini 研究 TSLA，
它顺手写一句"结合你当前 200 股的底仓"，这句话就躺在正文里了，没有任何字段能挡住它。

## 2. 三道闸

```
    你在后台粘贴
         │
         ├── ① 结构闸：这个仓库里根本没有"持仓"这个概念
         │      frontmatter 的字段是固定的（content.config.ts），
         │      没有 cost / quantity / side 这类字段可填。
         │      不依赖认字，是唯一一道绕不过中文花样的。
         │      「哪个智能体 / 哪个模型」也是封闭枚举（src/config/agents.ts、models.ts）——
         │      以前那个自由文本的 sourceModel 上公网而闸门不看，是个真泄露口。
         ▼
    存到本机磁盘（src/content/{posts,qa,pages}/*.md）
         │        ⚠ 此刻内容还**没离开这台机器** —— Keystatic 是 local 模式，
         │           后台只在 `pnpm dev` 里存在，公网上没有 /keystatic
         │
         ├── ② 暂存区闸：pre-commit（scripts/gate/check-staged.ts）
         │      查 `git show :<path>`，也就是**即将被提交的那份字节**
         │      装法：pnpm hooks:install
         ▼
    git commit → push（内容进私有仓库）
         │
         ├── ③ 构建期闸：pnpm build 的第一步（scripts/gate/check.ts）
         │      查工作树全量。不过就构建失败，**站上留着上一个版本**
         ▼
    Cloudflare 构建 → 公网
```

**仓库必须私有。** 第②③道站在"已经进仓库"之后，只有当公开的东西仅是构建产物时，
这个结构才成立。

### 为什么 ② 查暂存区而不是工作树

这两者会不一样，而且差错的方向是致命的那一边：

> 暂存了带泄露的版本 → 又把工作树改干净 → 查工作树：**通过** → 泄露照样进了 commit

反过来（暂存干净、工作树脏）只会多拦一次，是安全的方向。
2026-09-18 这条路径实测过：同一个文件，`pnpm gate` 放行、`pnpm gate:staged` 拦下。

### 扫哪些目录 —— 一张登记表，不是写死的路径

范围来自 `src/config/collections.ts`，两道闸都从它推：
构建期那道遍历 `scanned: true` 的目录，暂存区那道用同一份表生成路径正则。

> **2026-09-18 之前范围是两道闸各写一份的**：一个是 `join(cwd,"src","content","posts")`
> 拼的绝对路径，一个是字符串正则。两者之间没有任何共享符号 ——
> 于是 `src/content/pages/about.md`（一个公网页面，正文里就有一句 block 档的
> 「不写我自己的仓位」）**从建站起两道闸都没扫过**，而屏幕上照常印
> 「✓ 没命中已知的危险说法」、退出码 0。新建 `src/content/qa/` 也一样：
> `files.length` 因为 posts 还有稿所以 > 0，exit 2 不触发，**一个字的报错都没有**。
>
> 这正是第 7 节那个 `SC 13D` 事故的形态：两处各写一份、其中一处错了、全绿。

`scripts/gate/coverage.test.ts` 拿磁盘上的真实目录**双向**对账：
磁盘上有表里没有 → 失败（新集合没进闸门）；表里有磁盘上没有 → 失败（路径写错）。
`scanned: false` 的条目必须写 `scanExempt` 理由 —— 不许靠「没登记」来豁免。

### 报数按集合分，不许合并成一个总数

```
发布闸 (工作树)  研究稿 1 篇 · 问答 1 篇 · 单页 1 篇  共 3 篇，其中草稿 0 篇
```

把几个集合混成「扫了 3 篇」之后，「问答 0 篇」就藏在一个不可读的数字里 ——
而 qa 目录名拼错（`qas/` / `QA/`）**恰恰表现成「总数还是那么多、扫过了、通过」**。

退出码三档因此是：目录不存在 → 2；**所有**目录加起来 0 篇 → 2；
某一个集合空着 → **不是故障**（qa 上线第一天就是这样），靠逐集合报数让人看见。

> ★【2026-09-21】**这条设计真的抓到过一次。** 那天一次大改名提交里，
> 暂存区闸屏幕上印着「研究稿 0 篇 · 问答 0 篇 · 教程 1 篇」和一句绿 ✓ ——
> 而那次提交明明动了 3 篇研究稿、2 条问答。那几个 0 就是线索，
> 顺着它查出来的是下面那条 `--diff-filter` 的洞。
> 合成一个总数（「扫了 1 篇 ✓」）的话，这件事和"正常跳过"在屏幕上字节级相同。

### ② 查哪些路径：`--diff-filter=d`，**小写**

`git diff --cached --name-only --diff-filter=d` —— 小写字母是**排除**，
`d` = 「除了删除，其余全要」。

> ⚠【2026-09-21 踩到】原来这里写的是 `ACM`（新增 / 复制 / 修改），**漏了 `R`（改名）**。
> 那不是一个理论上的疏忽：git 判"改名"的相似度阈值默认是 **50%**，
> 也就是说**一次提交里改名 + 重写将近一半正文，整条记录仍然是 `R`**
> （实测 8 行里换掉 1 行报 `R066`）。于是那版过滤器**一个文件都列不出来**，
> 这道闸照常印一句「这次提交没有改动内容，跳过」，退出码 0。
>
> 那天那次提交里 7 个内容文件全被判成 `R`，暂存区闸只扫了 1 篇。
> 构建期那道（全量）照常拦得住，所以这是**第二道闸上的洞，不是通到公网的洞** ——
> 但第二道存在的意义正是"别让它进仓库"。
>
> **为什么是排除法而不是 `ACMR`**：列举法漏一个字母就是漏一类改动，而且零症状
> （`T` 类型变更、`B` 配对断裂同样会进索引）。排除法只排掉唯一一种
> "路径已经不存在、`git show :<path>` 会炸"的情况，git 以后新增的字母天然被包含。
>
> 钉子：`scripts/gate/stagedFilter.test.ts` —— 它造一个真的临时仓库、真的
> `git mv` + 改内容、真的跑一遍这道闸，断言它**拦下来**。不是比字符串。

### ② 拦不住什么

- `git commit --no-verify` 能绕过。这是 git 的设计，钩子挡不住存心绕的人。
  兜底是第③道 —— 它跑在 Cloudflare 上，绕不过。
- 它只看这次提交改动过的稿子。历史里已经躺着的由第③道全量兜。

## 3. 判定是三档，不是"通过 / 不通过"

| 判定 | 意思 | 后果 |
|---|---|---|
| `clean` | 没命中已知说法 | 放行 |
| `warn` | 命中了**意图**（"我打算买"） | 放行，但报出来 |
| `block` | 命中了**事实**（"我持有"、"我的成本"） | **发不出去，没有放行口** —— 只能改文案 |

★ **`clean` 说的是"这份稿子里没有我认识的危险说法"，不是"这份稿子安全"。**

词表必然漏 —— 中文表达一句话有二十种写法。所以屏幕上那句话是
「没命中已知说法 —— 注意：这不等于"安全"，词表必然有漏网」。
把"我没发现"说成"没有问题"，是这个项目最不能接受的错误。

### 收尾还要再分一档

「一个危险词都没有」和「有 3 处 warn 档命中」**不许压成同一句 ✓**。
后者恰恰是最该有人自己看一眼的那一档，压扁之后它在屏幕上就消失了。

> 【2026-09-18】中间这一档原来是「有 N 处是靠豁免放行的」。豁免机制删掉之后换成了
> warn 档 —— **不是随便找个东西来填坑**：warn 档在这之前一直被收尾那句绿 ✓
> **当场否认**（屏幕上先逐条列出 `own_intent` / `bare_position_term`，
> 紧接着印「✓ 没命中已知的危险说法」）。换过来顺手修掉了这个自相矛盾。

### 退出码也是三档

| 码 | 意思 |
|---|---|
| 0 | 放行 |
| 1 | 有稿子没过闸 |
| 2 | **闸门自己没跑起来**（找不到文章目录、一篇都没扫到） |

第 2 档绝不许和 0 合并：一次路径写错会表现成"扫描通过"，而闸门其实一个字节都没看。

## 4. 误伤是必然的

「机构持仓占比 62%」「持仓量创下新高」「单位成本同比下降 12%」都是正常的行情用语，
词表一定会咬到它们。

**所以每一条命中都摆出三样东西**：命中的原文、前后各 24 字的上下文、
以及这条规则为什么存在。只报一句"不通过"，等于让人去删掉正确的句子。

★ **2026-09-18 收窄过三处**，因为站里开始写开户教程，而那三条会把整个题材拦死：

| 改了什么 | 为什么 |
|---|---|
| `broker` → `own_broker`，**裸券商名那一半撤了** | 「在嘉信（Schwab）开户，盈透 IBKR 的流程放在下一篇」一句四处 block。教程的主题就是在哪家开户，名字是内容本身。第一人称那一半原样留着，而且更严了 |
| `own_position` 去掉 `拿着|握着` | 没有宾语约束。「我拿着身份证去网点做了面签」是 block 档 |
| 第一人称锚点**不许跨过「建议」** | 「我建议先别建仓」「我们建议加仓前先…」全中。教程通篇是建议语气 |

`gate.test.ts` 的 `MUST_NOT_BLOCK` 里钉了 11 句教程语料 —— 哪天有人把裸券商名加回去，
那一组会立刻红，而不是等到写第二篇教程时才发现整个题材发不出去。

压低误伤的办法是**第一人称锚点**：

```
我(?:们)?[^。！？；\n]{0,6}?(?:持有|持仓|建仓|…)
```

- `我` 后面允许夹几个字（"我这边的成本"、"我现在持有"）
- **但不许跨句** —— 句号、问号、感叹号、分号、换行是硬边界。
  没有这条，"别人怎么想我不知道。机构持仓 62%" 会被连成一条命中。
- 裸的「持仓」「成本」「加仓」**只进 warn 档**。删掉豁免机制之后这条取舍更硬了：
  进 block 会让每一篇稿子都被迫改掉正确的句子（「机构持仓占比 62%」是改不动的），
  闸门最后会被人整体绕过 —— 只是没人知道而已。

### 扫哪些字段

**所有会上公网的自由文本**：`title` · `description` · `contributor` · `tags` · 正文。

`tags` 是 2026-09-18 补的：它同样上公网（撑起整套 `/tags/` 公开页面），而闸门原本
一个字都不看 —— 实测 `tags: [我的持仓复盘]` 现在命中 `own_position`。

⚠【2026-09-22 搬家了，覆盖没断】这张清单上原来还有 `symbolName` / `symbolNameEn`
（公司中英文名，渲染在标的芯片的可见文本和 `title` 属性里；实测
`symbolName: "特斯拉（example_server 自动带出的中文名）"` 命中 `internal_system`）。
标的那一格改成**多选**之后，名字从条目上搬进了**标的表**
（`src/data/symbols.json`，后台「标的」那一页），条目上只剩代码 ——
代码是封闭词表里的值，夹带不进自由文本。
那两段字现在走的是本节末尾那条路（`SCANNED_DATA_FILES` + `inspectDataJson`），
**语料一个字没改，从 `coverage.test.ts` 搬到了 `registryGate.test.ts`**。
★ 所以这张清单上不许再留着那两个键名：扫一个 schema 里已经不存在的字段，
看起来像有保障，实际钉的是另一件事。

`contributor`（提示词的投稿人署名）是同日加提示词模块时补的。它比上面几项更该扫：
**这一项的字不是我写的。** 投稿人会在署名栏里写「某某（我的账户实盘跑了半年）」
这种话来证明自己的来路 —— 自己粘的字至少还过一遍眼，别人填的没有。
（`coverage.test.ts` 里有一条用例钉着它，实跑破坏过一次确认它会红。）

⚠ **这张清单是白名单：没写进来的 frontmatter 字段一律不扫。** 两个方向都要钉住 ——
漏扫是泄露（坑 7 那次 `about.md` 从建站起就没被扫过），多扫则是天天咬正确的句子，
而那会让人养成绕过闸门的习惯。`coverage.test.ts` 里有一条**负方向**的用例
（「没登记要扫的 frontmatter 键一律不进 subject」，探针用的是 `author`）。

⚠ `author` 不扫，而且**它也不许导出**：它是自由文本、闸门不看，站上印的是
`config.site.author`，条目里那个字段一个字都不渲染。见 7.5 节前提二。

⚠ `agent` / `model` 不用扫 —— 它们是 `z.enum(AGENT_IDS)` / `z.enum(MODEL_IDS)` 的封闭枚举
（`src/config/agents.ts` / `models.ts`），塞不进自由文本。
**但枚举背后那张登记表要扫**：【2026-09-20】智能体和模型的名字 / 厂商 / 说明挪进了后台
可编辑的 `src/data/registry.json`，那是人手填的自由文本，而且上公网（芯片、悬停提示、
导出件）。三道闸都拿它过一遍 `scan()`（`inspect.ts` 的 `inspectRegistry`，
`registryGate.test.ts` 钉着三处），路径只在 `src/config/collections.ts` 的 `REGISTRY_FILE` 写一份。

同理 `symbols`（标的）也是封闭词表，不用扫；**而那张表要扫** ——
【2026-09-22】公司中英文名从条目上搬进了 `src/data/symbols.json`（后台「标的」那一页），
路径登记在同一个文件的 `SCANNED_DATA_FILES` 里。
★ 这张名单**是 2026-09-21 加标签表那天长出来的**：在它之前三道闸里各写着一段只认
registry 的代码，再加一个数据文件就得改四处，而漏掉任何一处的症状是零 ——
那个文件安静地穿过那道闸，屏幕上照常印绿 ✓。现在加一份数据文件 = 在那张表里加一行。

## 5. 命中之后 —— 没有豁免口

**【2026-09-18 站长决定：整个豁免机制删掉。】** 原话是「不需要豁免机制，删除，
内容我自己会把握」。在那之前，误伤可以靠在 frontmatter 里写 `gateWaived` +
`gateWaiveReason` 放行一次。现在**那条路不存在了**：

> **命中 block 档的唯一出路是改文案。** 没有豁免、没有开关、没有环境变量。

怎么改：闸门拦下时会摆出三样东西 —— 命中的原文、前后各 24 字的上下文、
以及这条规则为什么存在。照着换个说法就行，通常是两条之一：

- **去掉第一人称。**「不写我自己的仓位」→「不写站长自己的仓位」。
  `about.md` 那句就是这么改的（它是全仓最后一条在用豁免的），语义一个字没变。
- **把话说成别人的。**「我的成本在 187」→「散户的平均成本线在 187 附近」。
  第一人称锚点不跨句，所以只要主语真的不是你，就不会中。

⚠ **不许用"把这条规则降成 warn"来解决一次误伤。** 那是拿全站换一句话：
档位是全局的，为一篇稿子松一格，后面每一篇都跟着松。真觉得某条规则的边界划错了，
走第 7 节的流程 —— 改规则表，并补一条从"人真的会这么写"来的用例。

### 删掉之后失去了什么

诚实地说一句：豁免记录本来会跟着内容进 git，`git log -p` 能查出谁在哪天豁免了
什么、为什么。现在**没有任何东西记得曾经有过误伤** —— 误伤发生时你改掉句子，
这件事就不留痕了。这是站长权衡过的取舍（一年未必用得上三次，却要在每篇稿子的
后台表单里常驻两个字段），不是疏漏。写在这里，免得以后有人以为是忘了做。

## 6. 规则表

在 `scripts/gate/rules.ts`。**只有这一份**，三个地方都读它：

1. `pnpm gate` / `pnpm gate:staged`（pre-commit）
2. `pnpm build` 第一步
3. 【2026-09-20 加】两个**只读、不拦**的预览：`pnpm dev` 里的 `/_gate` 页
   （`src/dev/gate.astro`，刷新即重扫工作树）和 `pnpm content:import` 写完稿子时
   当场跑的那一遍。两者都走 `inspect()`，和上面两道是同一份判据 ——
   它们只是把结果提前摆到人眼前，**不是第四道闸**，也没有任何放行口。

复制一份出去改，就是两道闸开始各说各话的那一天。

> 【2026-09-18】这里原来写着三个读者，第一条是「Keystatic 后台的豁免下拉框」。
> 那个下拉框随豁免机制一起删了。**顺带查实：`rules.ts` 文件头当时还写着
> 「Keystatic 后台的字段校验 —— 你粘贴的那一刻就报」，那句是假的** ——
> 后台从来没调过 `scan()`，它一个字都不校验。第一道防线一直是 pre-commit。

## 7. 改规则表的规矩

**必须补测试，而且用例要从"模型真的会这么写"来。**

不许照着正则反推用例。作者的另一个项目出过一次最贵的 bug 正是这个形态：
`FORMS` 里写的是 `SC 13D`，而 SEC 现网给的是 `SCHEDULE 13D`，
**87 条测试全绿，因为测试自己喂的也是 `SC 13D`** —— 断言和代码一起错，
而且零症状（备注写着「登记 0 份」，`ok=1`，告警零条，库里 109 行就摆在那儿）。

`scripts/gate/gate.test.ts` 里每一条 block 用例都是一句完整的、研究稿里真会出现的
中文，不是从 pattern 里抠出来的碎片。还有 6 条**不许误伤**的用例 ——
那一组比 block 那组更重要：闸门如果天天咬正确的句子，人就会养成整体绕过它的习惯
（`--no-verify`，或者干脆把规则降成 warn），到那时它已经废了。
删掉豁免机制之后这一条更要紧 —— 以前误伤还有一个合法出口，现在没有了。

跑：`pnpm test`

## 7.5 出站通道：新开一条的时候要重新钉两条前提

【2026-09-18 加了 `.md` 导出功能时补的】

这个站的内容出站一共有四条路。前三条（详情页 HTML / RSS / sitemap）有一个共同点：
**都只吐渲染过的正文**。2026-09-18 加的第四条不一样 ——
`/r/<号>.md`、`/q/<号>.md`、`/g/<号>.md`、`/p/<号>.md`
吐的是 **frontmatter + 原始 markdown**。

【2026-09-23 用户定的】它现在**只吐正文原文**：frontmatter、补上去的 `# 标题`、
文件头那段站方的引用块（「这是 … 的副本」/ 来路 / 免责 / 「模型的原话」）、
本地图片被换成的那句话，全都拿掉了。用户原话：「下载或者复制的时候会夹带平台私活，
禁止，是什么就下载什么，保持原文」（理由和历史在 `src/utils/exportMarkdown.ts` 顶部）。
正文正是闸门扫的那一段（第 4 节「扫哪些字段」），所以这条通道吐的字节**就是**
闸门扫过的字节，一个不多 —— 下面前提二因此从"靠一张白名单守着"变成了结构上成立。

同日第二轮（用户要的）：正文里的**本地图只换地址**，换成站上那张图的完整地址
（`https://lwj.ai/_astro/<文件名>.<hash>.webp`，和页面 `<img src>` 逐张相同）。
按上面那条判据过一遍：换上去的是**从构建产物算出来的地址**，不是谁写的自由文本；
文件名本身原来就在被扫的那条相对路径里。所以它不是新的出站内容。
⚠ 它**差一点**是一条新的出站通道 —— 不是字，是**原图**：算地址时要是拿
`import.meta.glob` 自己把 `src/assets` 下的图导一遍，构建会把每张被导入的原图发进产物、
事后只删做过变换的，没有页面在用的截图就连 EXIF 逐字节上公网（docs/engineering-notes.md 坑 15）。
所以 `src/utils/exportImageUrls.ts` 只查 Astro **已经为正文导入过**的那张表，
`export.test.ts` C 组钉着"不许 glob、不许读导入对象的 `.src`"。

它推翻了闸门的两条**隐含**前提。两条以前都只活在注释里，现在各有一条测试：

### 前提一：「闸门对草稿网开一面」的依据是**草稿不生成页面**

`scripts/gate/check.ts` 扫草稿、也报草稿，但草稿命中 block 档时**退出码是 0**
（实跑验证过）—— 因为它还没上公网。这条推理的全部依据是
`src/utils/postFilter.ts`：草稿和未到点的定时稿都不生成页面。

导出端点里少一句 `getSortedPosts()`，草稿就变成一个
**没有任何 HTML 页面兜底、却挂在公网上的 .md**。站上看不见、sitemap 里没有、
闸门照常绿、构建照常绿。人眼发现不了这件事。

→ `scripts/gate/export.test.ts` 的
「每个导出端点都必须过 postFilter（走 getSortedPosts）」。

### 前提二：「`author` 不必扫」的依据是**它永远不上公网**

第 4 节末尾说了扫描范围是一张白名单，`author` 不在里面。这条推理的全部依据是
**站上印的是 `config.site.author`，条目里那个 `author` 字段一个字都不渲染** ——
它是自由文本、闸门不看，只要不上公网就没事。

`matter.stringify(body, data)` 这种"省事"的导出写法会把整个 frontmatter
原样 dump 出去，正好把它发上公网。所以导出的 frontmatter 是
**白名单，不是黑名单**：`src/utils/exportMarkdown.ts` 里两张表
（`EXPORTED_FIELDS` / `WITHHELD_FIELDS`），schema 里的每个字段都必须在其中一张里
表态，沉默 = 测试红。

同一条判据还挡下了 `author`：自由文本、闸门不扫、今天一个字节都没上过公网
（站上印的是 `config.site.author`）。把它导出去，就等于把 2026-09-18 刚拆掉的
`sourceModel` 泄露向量原样装回来。

→ `export.test.ts` 的 A 组三条。

【2026-09-23】这一条现在是**结构上**成立的：导出件里没有 frontmatter，
`toExportMarkdown()` 的入参里根本没有那些字段（只收 `title` —— 只用于报错 —— 和 `body`），
新加一个字段不用去哪儿表态，它进不来。两张表和 A 组随之删了；钉子换成
`export.test.ts` 的 **B 组**（磁盘上每一篇真实内容逐字对账「导出 = 正文」）和
**C 组**（四个端点吐的就是 `toExportMarkdown()` 的原样返回值，只递 `title` / `body` 进去 ——
在返回值前后拼东西、或者多递一格 `data`，当场红）。

### 「复制全文」按钮**不是**第五条通道 —— 但它差一点就是

【2026-09-18 加复制按钮时补的】详情页上那个「复制全文」点下去之后，
**运行时 fetch `/r/<号>.md`**，把响应体写进剪贴板。所以它吐的字节
就是第四条通道吐的字节，一个不多 —— 它是第四条的一个触发器，不是新的一条。

这个性质**完全取决于一个实现细节**，而那个细节看起来像是可以随手优化掉的：

| 写法 | 是不是新通道 |
|---|---|
| 点的时候 fetch 那条 .md（现在这样） | **不是**。走的是同一个端点，`postFilter` 和 B / C 组都还在前面 |
| 把 `entry.body` 当 prop 传进组件、内联进页面 | **是**。那是第二个出口 —— 今天内联的正文和端点吐的一样，但哪天任一侧再变（端点那一侧历史上被加过一整段东西），下载和复制就**当场分叉**，而 C 组只钉得住端点那一侧 |

第二种写法省一次网络请求、页面照常、按钮照常、构建全绿。
（2026-09-23 之前第二行的理由是"绕开 `EXPORTED_FIELDS`、而且和端点吐的——图片摘过、
frontmatter 裁过——当场分叉"。导出件改成正文原文之后那两半都不成立了，
**结论没变**：读者拿走的东西只许有一个出口。）

「复制全文」验的是取回来的**不是一张网页**（`src/utils/looksLikeHtmlPage.ts`）。
2026-09-23 之前它验的是「必须以 `---` 开头」——导出件不再带 frontmatter 之后，
那一句会让**每一次**复制都报失败，所以换了；D 组拿磁盘上每一篇真实内容验它不误伤。
所以 `DownloadLinks.astro` 的 Props 里没有、也不许有 `body` / `entry` 这类东西，
`export.test.ts` 的 D 组钉着它。

### 新开第五条通道时，照这两条重走一遍

判据就一句：**这条通道吐的字节，是不是闸门扫过的那些字节？**
不是的话，它要么得自己过闸，要么得有一张白名单把范围收回到扫过的部分。

### 出站件里那句「这一份是谁写的」（2026-09-23 拿掉了）

【2026-09-23】这一句连同整段文件头一起拿掉了（见本节开头）。下面记的是它存在时的样子，
留着是因为那个事故形态 —— 一句全称断言铺在所有集合上、跟着文件离开这个站 —— 本身值得记住。
`provenanceOf()` 从此**没有调用方**（页面页脚那一句 2026-09-21 就删了），
等站长决定删掉还是另找落点（见 `src/config/provenance.ts` 顶部「现状」）。

【2026-09-20 加的】导出的 .md 里当时有一句按条目分档的来路声明，判据是
`src/config/provenance.ts` 的 `provenanceOf()`，**页面页脚读的是同一个函数**。

它不是新的出站通道：那句话是 i18n 里的固定文案，不含任何条目内容，
`provenanceOf()` 只读 `agent` 这一个**封闭枚举**字段（闸门不扫它正是因为它填不进
自由文本）。按 7.5 的判据过一遍：这条通道吐的字节仍然是闸门扫过的那些，外加
一句站方自己写死的话。

在它出现之前，四个端点无条件铺的是一句**全称断言**：「站内所有内容都是 AI 生成」。
那句话在只有研究稿和问答的时候是真的，加了教程和提示词之后是假的 ——
最难看的一份是读者投稿：frontmatter 印着 `origin: "读者投稿"` + `contributor: "某某"`，
紧接着的引用块说这是 AI 生成的，**当着署名的面否认作者**。而那份文件已经离开这个站了。

## 7.6 投稿：闸门第一次要过**别人写的字**

【2026-09-18 加提示词模块时补的】

在这之前，进入这个站的每一个字要么是我写的、要么是我从模型的聊天框里粘的。
提示词模块**收读者投稿**，于是多了一类载荷：**别人写的、我只看过一遍的自由文本。**

结构上它没有开新口子，这一点要说清楚：

- 投稿走的是**邮件 → 我看一遍 → Keystatic 后台建一条 → 提交 → 构建**。
  站上没有任何"提交表单"，也没有服务端 —— 所以不存在"投稿能自己落盘"这条路径。
- 因此每一条投稿都过**同样的三道闸**，和我自己写的稿子逐字节同一条路。

真正变了的是两件事：

1. **`contributor` 必须进扫描范围**（见第 4 节）。署名栏是投稿人自己填的、
   直接印在页面上的自由文本。
2. **「谁写的」必须是封闭枚举 + 哨兵**（`src/config/promptOrigins.ts`）。
   站长自己在用的 / 读者投稿（必带署名）/ 还没标 —— 三档，非草稿时哨兵挡构建。
   压成两档的后果不是难看，是**替别人认领东西**：一份来路不明的交易提示词
   显示成"站长自己在用的"，读者据此决定要不要照着跑。

⚠ 第 8 节那句"它挡不住词表之外的说法"在这里更要紧：投稿人不知道这个站有闸门，
也不知道词表长什么样。

**【2026-09-20 起这条链路上少了一道。】** 在那之前，页面上那块投稿说明
（`src/components/PromptSubmit.astro`）里明写着"别把自己的持仓、成本、券商账户
写进来" —— 那是唯一一道站在闸门**前面**、而且投稿人真的看得见的东西。
那一整块按用户要求删掉了（投稿入口改成 `/prompts` 顶上一句话 + 页脚邮箱）。
于是闸门前面只剩**人工那一道**：投稿信进后台之前站长自己看的那一遍。
写回一块投稿说明时，那句红线要一起写回来。

## 8. 它挡不住的

说清楚，免得把它当成保险：

- **词表之外的说法。** "手上这些"、"我这批货"、"成本线在 187" —— 中文太灵活了。
- **截图。** 闸门只看文本，看不见像素。截图里的账号 / 余额 / 持仓靠人在截图时
  自己裁掉或打码 —— 教程模块是截图为主的，这一条在那里最要紧。
- **裸 HTML 里的脚本** —— 那是**另一层**在管的，不是闸门。
  【2026-09-18 实测】这个站的 Markdown 会执行裸 HTML（Astro 那三处
  `allowDangerousHtml` 都是无条件的），而正文是从模型的聊天框里粘进来的。
  现在 `astro.config.ts` 的 rehype 链里有一层消毒（`src/config/sanitize.ts`），
  裸 HTML 会被转义成死文本。**它和发布闸是两件事**：
  闸门管"这段字该不该发出去"，消毒管"这段字发出去之后会不会执行"。
  测试在 `scripts/gate/sanitize.test.ts`，两组 —— 而**「必须活下来」那一组
  比「必须被中和」那一组更容易出事**（白名单写窄一格就会静默吃掉代码高亮，
  构建全绿、页面不报错）。
- **模型把数字编对了。** 这是另一个问题，不归闸门管（见 about 页那段）。
- **你自己按 `--no-verify` 再关掉 CI。** 三道闸都是机械的，但没有一道能防住
  下决心绕过它的人。它防的是**手滑**，而手滑才是真正会发生的那种。
